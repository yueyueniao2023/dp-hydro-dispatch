# 龙羊峡—拉西瓦：一年12个月联合调度

本例将两座电站的日入库资料聚合成12个自然月，以两站全年总发电量最大为目标。Java入口是 `monthly.MonthlyMain`，与单库、合成双库、四库教学案例同时保留。

原始龙羊峡末水位2600 m与12月生态下泄存在确定的水量冲突。程序输出原参数无解诊断，并按用户确认，将龙羊峡年末改为2595.2 m运行独立对照。来水按用户确认的含义：input4是龙羊峡外部来水，input5是两库之间的区间来水。

## 1. 先运行

环境为JDK 17+、Maven 3.x。在含pom.xml的项目根目录运行：

```bash
mvn test
mvn compile exec:java "-Dexec.mainClass=monthly.MonthlyMain"
```

第二条命令保留resourceData中的初末水位，**预期非零退出**，在 `results/longyangxia-laxiwa/original/summary.md` 中说明无解原因，同时保存日/月核算输入。Maven显示BUILD FAILURE表示发现题设冲突，不表示需要放宽约束来消除错误。

2595.2 m年末条件对照通过独立覆盖配置选择，具体有效区间模式见该配置及结果summary：

```bash
mvn compile exec:java "-Dexec.mainClass=monthly.MonthlyMain" "-Dexec.args=data/longyangxia-laxiwa results/longyangxia-laxiwa/comparison data/longyangxia-laxiwa/comparison.properties"
```

覆盖配置只替换列出的项目，其余继承 `dispatch.properties`，默认 `interval.mode=input5-as-interval`。IDEA中直接运行 `monthly.MonthlyMain`，工作目录为项目根目录；Program arguments填上述三个路径。`--help` 可查看用法。

## 2. 文件和参数

源文件原样保留在 [raw](../data/longyangxia-laxiwa/raw/)，字段对应关系见[数据说明](../data/longyangxia-laxiwa/README.md)。

| 参数 | 龙羊峡 | 拉西瓦 | 处理方式 |
| --- | ---: | ---: | --- |
| 正常蓄水位m | 2600 | 2452 | 默认各月水位上限 |
| 死水位m | 2590 | 2440 | 各月水位下限 |
| 初水位m | 2598.3 | 2452 | 精确边界，不取整 |
| 原末水位m | 2600 | 2452 | 原场景精确边界 |
| 最大发电流量m³/s | 1192 | 2280 | 机组过流上限 |
| 出力系数 | 8.5 | 8.5 | 综合系数，不重复乘效率 |
| 最大出力（暂按MW） | 1280 | 4200 | 发电出力上限 |
| 最大总下泄m³/s | 6000 | 6310 | 发电加弃水总流量上限 |
| 保证出力（原数值） | 60.9 | 99 | 保留参数，可选逐月硬约束 |

生态下泄使用ecoFlow4/5的12行月值：龙羊峡全年552 m³/s；拉西瓦5、6月400，其余月200。resourceData中的生态流量为基本参数，逐月表优先用于月变化。

resourceData其他字段中，机组数量×单机装机与最大出力一致，机组数量×单机过流与最大发电流量一致；额定水头是设备参考点，不代替随水位变化的实际水头。泵站效率不用于本次无抽水模型。保证出力通常需要保证率及统计定义，资料没有这些信息，默认不把它强制成“每个月必须达到”；`enforceGuaranteedPower=true`可显式采用这种更强的解释。

原表未标年份和单位。本例假设365行按平年1月1日至12月31日排序、水位m、流量m³/s、库容亿m³、出力MW。`storage.toM3=100000000`、`power.toMW=1`暴露单位假设；保证出力是否与最大出力同单位仍需资料提供者确认。修改单位会改变结果，不能把解释假设写成已核实事实。

**按用户说明，zPlanLYX与本次调度无关：程序不读取该文件，也不用于计算区间来水。** 对照中的2595.2 m是用户明确接受的替代末边界，由配置直接给定。

## 3. 按用户确认的来水含义直接耦合

本次用户明确解释：不考虑龙羊峡上级电站，input4就是其外部来水；input5已经是龙羊峡—拉西瓦之间的区间来水。因此默认实现为：

```text
龙羊峡本月入库 = input4当月日均值
龙羊峡本月总出库 = 本月入库 + (月初库容-月末库容)/当月秒数
拉西瓦本月入库 = 龙羊峡本月总出库 + input5当月日均值
```

这正是用相邻月水位、库容曲线与水量平衡反推上库出流的模型。上库总出库包含发电流量和弃水，两库之间不考虑传播损失或时滞。input5不减input4，也不需要用计划水位还原，更不设为0。

来源存在一处含义差异：原《数据说明.txt》写“对于拉西瓦，需要处理为区间流量”，《各水电站input.xlsx的意义.xlsx》将其标为“入库流量”。本次实现以用户明确确认的“input5已为区间来水”为准，原文件原样保留供后续向提供者核实。若今后证实另一个数据集的input5实际为下库总入库，才需要上库实际出库或储量变化来还原区间，不能直接套用本次模式。

为便于以后替换数据，程序保留以下显式模式；本次成果只采用第一行：

| interval.mode | 所需资料 | 行为 |
| --- | --- | --- |
| input5-as-interval | 本次用户已确认的input5 | 直接按月聚合为区间来水 |
| missing | 无 | 用缺失值占位，只做独立可证明的上库诊断，拒绝梯级求解 |
| zero-assumption | 明确选择此假设 | 全年区间来水为0；input5仅保留供核对，不作拟合或反推 |
| monthly-net | interval.file指向CSV | 读取12个月净区间流量，保留有依据的负增损 |
| daily-upstream-release | interval.file指向XLSX | 365行龙羊峡实际日总出库，逐月计算input5减实际出库的均值 |

monthly-net文件格式为UTF-8，必须有表头及严格连续的12个月：

```csv
month,interval_net_inflow_m3s
1,此处填写真实月均净区间流量
```

上面的文字只是格式说明，不是可运行的虚构数据。daily-upstream-release需单工作表、无表头第一列365个数值，并与input5日时点一致。两种外部资料模式均须确认传播时滞口径；如果出现负值，必须解释为净增损或先核实资料，程序不擅自截零。

优化后的拉西瓦入库由 **龙羊峡本月优化总泄流 + 区间净流量** 决定，包含上库弃水。input5在本次是其中的区间项，不是全部入库。

## 4. 原参数为什么无解

12月有31天，龙羊峡平均入流310.612903 m³/s，生态总泄流至少552 m³/s。即使12月初已达最高允许水位2600 m，12月仍须消耗：

```text
(552 - 310.61290322580646) × 31 × 86400
= 646531200 m³ = 6.465312 亿m³
```

所以12月末一定低于2600 m。水位库容曲线给出的理论最高年末约为 **2598.290707 m**；这一上界还未考虑更早月份，不能视为已证明全年可达。此冲突与区间假设、下库决策和网格步长均无关。程序先做这项必要条件检查，然后才启动DP。

对照场景把龙羊峡年末明确改为2595.2 m，拉西瓦仍为2452 m。它改变了全年可释放水量，因此只能评价该边界下的结果，不能与原始无解场景计算所谓“发电提升率”。

## 5. 月尺度水量与电量

一个月有D天，则秒数Δt=D×86400，小时数Δh=D×24。日平均流量按当月天数求平均，乘月秒数后与逐日水量总和一致，不统一用30天。

```text
R上 = I上 + [V(Z上初)-V(Z上末)] × 1e8 / Δt
I下 = R上 + I区间
R下 = I下 + [V(Z下初)-V(Z下末)] × 1e8 / Δt
Z尾 = 尾水曲线(R总)
H净 = (Z初+Z末)/2 - Z尾 - 损失水头
Q发电 = min(R总, 最大发电流量, 装机MW×1000/(A×H净))
Q弃水 = R总 - Q发电
P(MW) = A × Q发电 × H净 / 1000
E(MWh) = P × Δh
```

1亿kWh=100000 MWh。尾水位由总泄流决定；装机限发后多出的水记为弃水，不能丢弃。每期同时检查两库水位、生态下泄、最大泄流、机组流量、出力及可选保证出力。

当前没有逐月汛限表、独立变幅限制、损失水头资料或机组效率曲线。默认各月上限为正常水位，损失水头为0；可通过12项 `upstream.monthlyLevelLimits` / `downstream.monthlyLevelLimits` 补充整月持续上限。这一上限同时约束月初和月末，不能直接混用只约束月末的计划值。

## 6. 联合动态规划

阶段为月，状态为月末两库水位组合。状态价值是到达该组合时已经取得的最大累计发电量：

```text
F[t,u,d] = max(F[t-1,u0,d0] + E上 + E下)
```

前一期两库状态和本月末两库状态决定两条水量平衡。只初始化指定初值，其余状态为负无穷；末月只接收指定终点，通过保存前驱回溯12个月结果。复杂度为O(12×N上²×N下²)，上库重复计算在内层外缓存。

默认网格步长0.5 m，并额外加入精确的初末水位，不将2598.3或2595.2四舍五入。结果是在该离散模型内的全局最优，不能称连续水位最优。可用0.25 m及0.1 m重复运行独立目录检查敏感性。

## 7. 曲线质量与适用边界

原始库容数据存在未用低水位段异常：v4第368→369行从135.88降为131.16，第519→520行从182.93降为182.26；v5第42—46行连续为4.879。代码不猜改原值，只截取覆盖运行范围的片段并包含插值邻点，检查该段水位与库容严格递增。未用异常写入summary；以后运行范围进入异常段将报错。

q5尾水曲线从380 m³/s开始，低于380的尾水关系未提供，即使生态要求允许更低泄流，程序也不静默外推，而是拒绝缺曲线支持的转移。因此最优性针对提供的曲线覆盖域，不代表低流量段也已经验证。

模型使用月平均流量及初末平均水位，忽略月内波动与传播时滞，不包含风光、抽水、储能、电价、电网平衡、机组启停及日内防洪。月生态约束不证明每天都达标。它适合学习月尺度水电梯级联合优化。

## 8. 输出与核验

- `summary.md`：当前场景、可行性、有效配置、数据警告及电量。
- `monthly-inputs.csv`：12个月来水、区间量和约束。缺失数据为空白。
- `daily-inputs.csv`：365个原始日入库及可选实际出库。
- `dispatch.csv`：12行完整水位、库容、总泄流、机组流量、弃水、水头、出力、电量及守恒残差。
- `monthly-summary.csv`：中文表头的简表，可用Excel打开。
- `charts.png`：两库水位及月电量。

无解时不生成调度轨迹，并清理同目录由本入口生成的旧成功结果，避免误读。单元测试覆盖独立完整路径穷举、耦合含弃水、精确初末、负净区间、缺资料拒绝、计划文件不参与、月水量守恒、无解证明和曲线异常。结果及网格敏感性实测记录见仓库主README的新增案例入口和结果目录。
